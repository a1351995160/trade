# 全池长期研究：从提交规则到可核对结果

本入口让你提交一份固定策略，系统先检查整个登记股票池，回测全部资料合格股票，再分别说明“账户赚了多少”和“信号本身表现怎样”。策略提交后，计算由确定性的程序完成，运行程序不需要 AI 持续在线。AI 是否能够无人值守调用模型、寻找盈利策略，仍是另一项能力，不能由本入口替代。

## 对普通用户的变化

| 以前容易混淆的事 | 新入口的处理 |
|---|---|
| 计算时间快到上限，就把历史区间截短 | 交易区间事先固定；程序分段运行，继续同一个账户 |
| 把“账户日”当成必须持股的天数 | 账户日是每天核对资产的交易日，空仓也算；持股天数仍由买卖、止损止盈及最长持有规则决定 |
| 几千个信号最后只有十几笔成交，就判断信号无效 | 分开报告信号、排名、计划、资金和仓位约束、订单及实际成交 |
| 多只股票同时满足条件，默认代码顺序决定买谁 | 新规则版本可冻结一个评分及排序方向；同分时按证券代码排序 |
| 程序中断以后从头重跑或重复扣额度 | 从已保存的完整状态继续，同一用途累计时间，不重复建立账户用途 |
| 账户历史收益为正，就称为合格策略 | 账户核对、信号研究、独立数据验证、正式评审及 Paper 资格仍分别判断 |

“全部股票”指维护者登记的数据目录内的全部目标证券，包括登记的深圳主板、上海主板、创业板。它不等于无条件承诺整个 A 股历史均可投资。系统检查完整分母，公布资料不合格的逐股原因；通过检查的全部股票参与回测，随后才由策略信号和排序选股。

## 提交的内容

使用公共请求 `FULL_UNIVERSE_SUBMISSION_V3`，并保持 `account_scope=DATA_QUALIFIED`。提交内容包括数据目录、预热与评价区间、实际资金、仓位上限、正常及压力成本、买卖规则、止盈止损、长期资源规格和信号观察计划。不接受手工指定少数 `symbols` 缩小登记范围。

已有 `RESEARCH_RULE_STRATEGY_V3` 买卖和退出规则可以继续使用。需要明确同日选股顺序时，使用 `RESEARCH_RULE_STRATEGY_V4`，在 `selection` 内冻结数值评分、`ASCENDING` 或 `DESCENDING`、以及 `SYMBOL_ASCENDING` 同分顺序。技术指标可组合使用；评分专用指标未完成预热时，系统记录“评分未知”，不能借此把原始信号抹掉。

止损和止盈属于 `rule.exits`，不是随意添加的后端参数。支持范围以公共 `capabilities` 的当前版本为准。现有退出语义为收盘确认、下一交易日开盘尝试成交，停牌、涨跌停、可卖数量、开盘跳空和成本仍可能影响成交，止损线不保证就是成交价。

## 区间与资源

规格必须从 `universe_execution_profile_v1.execution_profile()` 或公共能力目录取得完整登记描述，不手工编造哈希或扩大超时值。

`account_sessions` 是冻结交易所日历中评价区间的**实际交易日数**，不是自然日数，也不是允许任意日期范围的模糊上限。实际日历与声明不符时，系统拒绝运行。普通研究支持 1～504 个账户交易日：不超过 252 日的每个计算用途累计最多 4 小时，253～504 日最多 8 小时。每个工作进程最多 900 秒、2048 MiB、单计算线程，同一任务串行派发。

准备资料、账户回测、独立核验、研究报告分别需要已有授权。账户正常成本与压力成本各有一个用途；准备、核验、报告各消费自己的固定额度。换段不产生新的策略尝试或免费计算，停机等待不算活动计算时间，但授权的绝对到期时间持续前进。无法确认崩溃进程实际消耗时，保守扣除已派发段的上限。

资料读取和资格核验也计入实际计算时间。每个新进程都会重新检查完整父资料、合格范围和冻结文件；同一个进程可以复用刚刚严格核验通过的资料。资料内容、使用区间或指标要求改变时，旧核验不能继续使用。这种复用不改变股票范围、账户结果或独立核账要求。

逐行查询时，每个字段只读取一次，避免同一文本重复解码；重复的证券状态时间文本最多缓存4096项解析结果。这个小缓存不保存证券是否合格或当时是否可见的判断，每次查询仍按当前来源、状态和决策时刻重新核对。缺值、错误日期、未来可见时间及冻结输入身份的处理不变，缓存也不延长运行时限。

冻结文件继续按每批最多8192行读取。原声明为对象的重复文本，每批只解码不同的值，再按原行顺序展开；空字符串、中文、`None`、字段类型及输入身份仍保留。核对价格衔接时，同一分红送转事件的日期只解析一次，再逐日检查它是否落在报价之间；日期无效仍保留原有阻断。这些优化不省略父资料或合格范围核验，也不共享不同账户的交易结果。

准备阶段只复用本次新读入的内部数据表，完整的来源、日期、资格和输入身份检查继续执行；公开的输入构造器仍隔离调用方提供的可变数据表。临时文本字典逐批使用系统内存池，不会更换进程默认的 Arrow 内存池。完整准备和独立加载必须分别实测，单独加载通过不能代替全流程内存验收。

合并冻结文件的读取批次时，每完成一列就释放该列的批次副本，避免旧批次与整份新表同时占用内存。原字段类型、空值、列顺序和行索引保持一致；父资料、合格范围以及正式子资料仍分别完整核验。加载内存实测还须包含实际账户入口的模块和配置准备；简化加载器通过不能代替真实账户启动验证。

独立核验会从原始历史重新计算自己的指标，并逐只保存已经核对的结果。中断后先检查来源、区间和保存内容，再接着处理剩余股票；没有提交完成的股票重新计算。它不拿账户执行器的指标缓存当作正确答案，也不会因为换段重置递归指标。

维护者必须在冻结前登记全部资源规格及额度，包括 `execution_profiles`、`compute_authorization` 的 `preparation_jobs`、`verification_jobs`、`report_jobs`，以及精确的账户许可。普通公共预览不接受 `ENGINEERING_CONTINUOUS_REFERENCE_V1`；该规格只给工程验收建立独立连续对照账户，须另行明确工程用途授权，不能通过修改已经冻结的作业来获得。

## 实际使用

查询新版本的真实工程验收凭证可运行 `python scripts/run_trusted_research_v1.py publication --long-horizon`，不需要部署配置，也不读取行情数据源或启动账户。原 `publication` 命令仍查询旧凭证；任何凭证通过都不授予策略有效性或 Paper 资格。

公共命令沿用已有部署配置和不可变授权，不需要为每份新策略增加采集、账户执行或核账脚本。以下占位值替换为真实路径及前一步返回的身份：

```powershell
python scripts/run_trusted_research_v1.py capabilities --workspace-root <工作区> --deployment <部署配置.json>
python scripts/run_trusted_research_v1.py preview --workspace-root <工作区> --deployment <部署配置.json> --request <策略请求.json>
python scripts/run_trusted_research_v1.py freeze --workspace-root <工作区> --deployment <部署配置.json> --request <策略请求.json> --preview-identity <preview_identity>
python scripts/run_trusted_research_v1.py approval --workspace-root <工作区> --deployment <部署配置.json> --task-id <task_id>
python scripts/run_trusted_research_v1.py approve --workspace-root <工作区> --deployment <部署配置.json> --task-id <task_id> --preview-identity <preview_identity>
python scripts/run_trusted_research_v1.py start --workspace-root <工作区> --deployment <部署配置.json> --task-id <task_id>
python scripts/run_trusted_research_v1.py status --workspace-root <工作区> --deployment <部署配置.json> --task-id <task_id>
```

也可先运行 `scan` 检查范围。`freeze` 会复用同一身份的已核对检查，保留全部登记目标数、全部合格数与排除明细。

`start` 是确定性的执行服务，按同一用途自动派发后续段并完成核验和报告。通过工作台启动后由服务线程执行；通过命令行启动时要让该命令的宿主进程持续运行。关闭 AI 对话不会取消已启动程序，关闭宿主程序则需要恢复。

请求暂停和恢复使用同样的 `--workspace-root`、`--deployment`、`--task-id`，把子命令换为 `pause` 或 `resume`。暂停在已保存的完整边界生效；恢复前必须证明旧工作进程已退出，不能同时重复派发。已知失败不会被当成正常暂停自动重试，原授权已到期或资源已经耗尽时也不能通过恢复清零。

Windows 上查看进度可能短暂占用正在更新的文件。保存完整收盘时，程序先写好并同步独立临时文件，再原子替换进度；只对 Windows 的短暂访问或共享拒绝最多等待 1 秒，始终重试同一份完整临时文件。旧收盘内容在成功替换前保持完整，持续拒绝访问或其他错误仍失败。这段等待计入原工作进程时间，不延长资源额度，也不重跑已经失败的账户用途。

派发时间包含启动和收尾，系统给工作进程预留最多 10 秒的宿主收尾时间，登记的 900 秒上限保持不变。已经派发的计算即使随后到期、暂停或撤销，仍会结清原消费；这不授权新的计算。已知失败但宿主收费回执丢失时，按原段上限关闭为失败；已知实测超耗则完整保留实际耗时、超耗和失败原因，冻结额度不变，不能把超耗裁成成功。父研究预算同时记录真实债务并暂停后续派发。

长期分段程序从工作进程启动时共同计时，资料读取、账户、核验和报告不能各自重新领取一段时间。程序另预留 60 秒保存完整边界并退出；标准段用于业务计算的窗口约为 830 秒。这个余量不是延长上限，也不保证任意工作量都能及时完成；操作系统仍强制执行资源边界，实际超耗仍按失败处理。剩余额度不足时窗口进一步缩短，不能恢复成完整 830 秒。原始派发额度连保存余量都不足时，明确结束为资源不足的失败，不反复派发无实质工作的段。

若账户结果和最终状态已经写出、只有宿主回执在崩溃中丢失，恢复保留原结果字节。原段仍按未知耗时保守收费，随后在同一用途的剩余额度中派发一次有界尾部核验；它核对原结果及最终快照，不重放已完成的交易日。准备和报告的失败也保留带原段身份的失败原件，不能换名称或换授权登记别名重新获得同一计算额度。

旧 `FULL_UNIVERSE_SUBMISSION_V1/V2` 作业及其 900 秒行为保持原样；不能往旧作业里加新字段后沿用原哈希。

## 怎样读最终报告

每个成本账户包含账户研究报告、信号研究报告、逐日信号漏斗、成本与资金约束说明，以及可核对的日明细分片。报告计算自身也有完整边界和受限资源记录，中断后继续自身汇总，不把交易引擎给出的资产数直接当作独立核账答案。

最后生成报告时，系统复用本进程已严格核验的全市场资料，继续检查原输入身份、完整日期范围、资金和结算结果；不会为了排版再加载一份行情。价格基准沿用原来的期初选股条件，不继承策略指标的预热要求。排版与价格基准计算也受同一进程截止时间约束，部分文件已写出不能单独证明报告阶段成功。

账户报告回答实际资金下成交了哪些股票、费用、分红、收益、回撤和空仓情况。信号报告对全合格范围的固定买入信号观察 5、10、20 个交易日后的表现，并使用同日、同持有期、同范围的对照。信号观察允许每个信号独立观察，不受同一个 5 万元账户的仓位槽位限制；因此它不能被称为一份可直接投资的账户收益。

买入数量分配完成后，成交时还会重新检查风险。组合的资金、费用和当前持仓限制先检查；通过后，原有风控继续检查前一收盘权益对应的单股上限和持仓数量。因此，开盘持仓升值使分配数量增加，也可能随后被前收盘权益上限拒绝。新版独立核验按同样的先后顺序分别计算原因，报告保留真正拒单环节的原因，不把这些拒单统一称为资金不足。

观察计划在运行前固定。以次一交易日原始开盘价作为观察起点、指定持有期的原始收盘价作为终点，并核对公司行动带来的经济权益；区间末尾没有足够未来交易日的信号单独标为样本不足，不能补看未授权数据。该报告只解释已授权历史上的信号表现，不会把已用于设计的历史重新命名为独立验证。

工程测试通过说明这一入口及核验逻辑在相应夹具下可用。全池长周期真实数据验收须有独立证据；真实账户跑通也不意味着未来盈利。正式资格、统计方法适用性、独立数据验证和真实 Paper 观察仍按各自规则判断。

## 停牌期间遇到分红或送转

新长期后端明确登记价格规则 `CAUSAL_SUSPENDED_CASH_AND_SHARES_V3`。如果除息日没有真实成交行情，系统先核对交易日历、原始资料和整个缺口的停牌状态，再用分红送转条款与复牌后的官方昨收相互核对。在首个真实复牌行情上衔接指标价格；不会补造停牌日的开盘、收盘或成交量。缺少来源、状态未知或参考价格冲突仍拒绝运行。

账户的交易日期继续经过这些停牌日。已持仓股票发生现金除息时，分红权益增加，股票估值也应相应扣息；送转同时调整股份数量。新账户和独立核账各自计算这一变化，并保存事件、估值及恢复证据。停牌期间的估值只使用已知条款和此前价格，不提前使用未来复牌价格。

这段停牌估值规则为 `MODELED_SUSPENDED_EX_REFERENCE_V3`：它是公开的模型估计，不是当天可以成交的价格，也不把现有 `MODELED` 历史可见性升级为已经证实。真实数据核对通过与策略取得正式资格仍是两件事。旧版本的价格规则及已冻结任务不被静默改写。

## 维护者继承已有资料

扩展长期数据时，`prepare_long_horizon_data_v1.py` 以登记清单中唯一的 `SOURCE_QUALIFICATION` 文件为依据，并核对其哈希和完整股票分母。旧清单中的提示路径可能过期，提示不能替代已经登记的原件。

旧公告审核记录中的相对路径，以显式传入的 `--legacy-root` 为根目录解析，支持 `/` 和 `\`；不会从运行命令时的当前目录找同名文件。绝对旧路径失效时，只接受该根目录内对应项目路径的同字节副本。路径越界、目录重定向或内容哈希不符都会拒绝继承，原件与旧声明不改写。

这种整份来源转换属于一次性数据维护，须单独记录受限作业、实际时间、内存峰值和失败记录。它不替代公共入口中分别收费的准备、账户、核验和报告，也不能通过调整维护时限扩大已经冻结的账户资源规格。
