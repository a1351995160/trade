# 全池初始化中的重复状态核查优化

全池账户在进入逐日交易之前，需要验证每只股票在每个交易日的行情、证券状态和公司行动资料。本次只减少其中一项重复工作，仍完整检查父池、派生合格范围并核对正式子输入。

同一份冻结证券状态如果在当天开盘已经可见，那么到当天收盘仍然可见。覆盖审核先取得开盘状态；只有开盘状态未知时，才额外查询收盘状态。午间才可见、全天未知、时间无效或来源不合格的情况，仍保留原来的缺口和阻断结果。

实现位于 `universe_account_inputs_v1.py` 的 `_coverage()`。没有增加跨进程缓存、改变原始数据或修改输入身份算法；公开 `state()` 查询仍按调用方指定时点独立判断。交易信号、止盈止损、成交、记账和费用规则没有变化。

## 工程验证

合成回归覆盖日记录及区间记录、开盘已知、午间/收盘后可见、未知和错误时间、来源、板块、生命周期冲突，以及开盘与收盘缺口原因不同的情况。测试比较优化前实际生成的覆盖输出摘要和输入身份，并检查开盘未知时仍执行收盘核查。

另有小型合成资格派生剖析，包含120只人工生成股票、60日预热和504日账户日历。它只验证资格结果与输入身份保持一致，以及重复查询次数减少；不读取本地真实行情，不产生真实账户结果。
