# 结清边界的治理源码接续

人类在 2026-10-26 明确批准“受限版本接续，保留检查点继续”。本次仅为同一人工任务安装已验证的治理读取器，沿用原任务根、原经济计划、已提交日、全部费用、Owner、额度和绝对截止。原版本协议的一次切换记录保持原样，新协议使用独立批准摘要、manifest 和独占槽位。

## 范围与校验

允许更换的文件仅为 `campaign_scope_v1.py`、`account_purpose_time_extension_v1.py`、`failed_account_recovery_v1.py`、`account_version_continuation_v1.py`，另增接续协议自身。任何已进入冻结经济或运行计划依赖的文件均禁止更换。原计划 ID 和历史版本证明不变。

优化只针对已解析 JSON 树的等价编码、摘要和独立复制。读取到的 Owner JSON 摘要走等价的 JSON 编码路径；一般调用者的 `require` 仍保留原通用规范化行为。两条路径共用全部批准、原件身份和内容比较断言，每次调用都重新读取批准记录，哈希前后继续检查协作截止。没有跨调用的文件系统元数据、许可或账本重放结果缓存。

安装必须在公开 PAUSE、无活动段、无 UNKNOWN、母子已结清的边界进行。摘要绑定该边界的检查点副本、已完成日数、费用、下一段编号、账本字节前缀及既有侧车。原 Owner 对新摘要单独批准。新进程重新读取全部证明后，才能公开 RESUME 并从下一未完成日继续。BASE 已完成时不得再次派发 BASE。

新段的 `EXECUTION_VERSION` 记录增加 `governance_source_revision`，绑定本次 manifest、首次允许段号和原 dispatch identity；原 RESOURCE SHA 与唯一母子收费继续使用原验证链。历史 RESOURCE、CHARGE、EXECUTION_VERSION、检查点前缀及 Owner 原记录不改写。新增的保留槽使旧读取器按原“唯一 manifest／槽位”规则拒绝回退后派发。

安装没有自动重试或静默回滚。出现部分写入或 fresh 校验失败时停止，保留证据与已完成检查点，不能用旧许可继续。
