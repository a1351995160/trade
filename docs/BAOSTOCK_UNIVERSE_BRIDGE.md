# 旧资料复用与全股票池补齐

系统可以先复用已核验的 BaoStock 原始资料，再补缺失部分。策略仍通过同一个公共入口提交，不必为每个新策略编写数据接入、批量执行和核账脚本。

“已有行情”与“账户能可信计算”是两件事。价格用于产生信号；股票状态用于判断是否上市、是否停牌或 ST；分红、送转及除权资料用于核算持仓和收益。资料不完整的股票仍留在目标名单中，报告会说明缺什么，不能只留下资料齐全的少数股票后声称全市场完成。

## 这次接通了什么

旧 BaoStock 原始响应采用 `BAOSTOCK_FULL_UNIVERSE_V1` 登记，通达信资料继续采用 `TDX_FULL_UNIVERSE_V1` 登记。两者进入相同的股票范围、指标、账户和核验流程，来源名称与原件哈希各自保留。没有把通达信数据改名成 BaoStock。

同一份冻结策略、同一日期、同样资金的新旧入口对照，分别运行正常和压力成本。逐日对照包括买卖决定、成交、现金、持仓、权益、费用、分红及分红税。不同入口的计划编号分别保存；新增审计说明须核对具体分红事件和到账记录，不能直接忽略账户差额。已完成作业可以只读复核，不重新批准、运行或消费预算。

旧年度文件按实际查询口径重新登记，不改写原件。`report` 指预案公告年份，`operate` 指除权除息年份；文件名里的年份不能替代年度覆盖证明。原件中的具体可见时间必须保留，缺换手率也不能用估算值冒充。

## 资料怎样补齐

当前目标由已登记的历史名单确定，包含深圳主板、上海主板和创业板。缓存缺失先找本地通达信原件；已有 BaoStock 行情先核对查询范围、原件哈希及与通达信的价格一致性，再用于股票状态和前收盘价。分红、复权事件日期按“股票＋年份＋缺失资料”列出请求。

补采器冻结完整队列，每批最多九项请求，记录实际请求数、原响应、开始记录和完成见证。再次执行时核验已成功的原件，不重发已完成请求。部分失败保持明确阻塞，不无限重试，也不假装没有消费过请求。

公司行动准备使用有完成见证的批次，也可复用阻塞批次中逐项独立核验成功的原件。后者必须核对请求开始记录、查询、来源、时间、原件和响应内容哈希；原批次仍为 `BLOCKED`，不能改成完成，失败响应不取得资格。完整的 `operate` 年度响应、复权事件日期和现金条款共同构成证明；空响应还需要交叉核对，不能凭空写成“没有分红”。送转、配股、缺条款或来源矛盾会保留缺口。旧 `report` 文件导致的漏采另列追加队列，排除主队列中所有已完成和待执行请求；已有较宽的复权查询覆盖本次窗口时也不重复申请。

扫描允许资料齐全的股票继续计算，其余股票显示“未知”，并保留全部目标作为分母。整池账户运行仍要求完整账户资料通过检查。资料准备器本身不授予账户运行资格、独立验证资格或策略资格。

## 历史状态模型要分清

全市场旧日线原件没有证券状态的当年发布时间。本次新数据集明确采用 `MODELED_SAME_SESSION_VENDOR_STATE`：将该日原件中的状态作为该日交易状态的模型假设，并保留原件实际采集时间。这与旧归一化数据集的 `NEXT_SESSION_OPEN` 模型不同。旧数据集及其时间记录保留，新数据集重新绑定来源和身份，不能拿旧模型的证据证明新模型已核实。

这两类历史模型均不等于“已证明当时可见”。带明确可见时间的原件不能静默改成同日假设；全市场准备器遇到暂不支持的具体时间字段会保留缺口。若研究必须使用原来的保守时间模型，应继续登记原清单。

## 维护者操作

以下是资料维护命令，不是新策略专属代码。路径替换为维护者已登记的实际清单与输出目录；所有新产物保持不可覆盖。

```powershell
# 旧 BaoStock 原件复制登记；源文件保留。
python scripts/prepare_baostock_universe_data_v1.py --source-root <原件目录> --source-manifest <旧清单> --master-manifest <历史股票名单清单> --output-root <新目录> --universe-id <登记范围编号> --feature-start <预热起日> --account-end <结束日>

# 已完成的新旧账户对照，只读复核，不新建作业或消费预算。
python scripts/run_baostock_universe_parity_v1.py --reverify <PARITY_RESULT.json>

# 从本地通达信原件补回缓存中缺失的目标。
python scripts/prepare_missing_tdx_cache_v1.py --help

# 复用已有全市场 BaoStock 原件，形成状态、前收盘价及缺口队列。
python scripts/prepare_universe_supplements_v1.py --help

# 顺序执行冻结缺口；没有阻塞时，同一命令可核验恢复已完成部分。
python scripts/collect_universe_gaps_v1.py --batches <ACQUISITION_BATCHES.json> --output-root <新采集目录>

# 原采集已阻塞时：只读核验成功项，显式生成剩余请求的新队列。
python scripts/prepare_universe_collection_continuation_v1.py --collection-root <原阻塞采集目录> --output-root <新续采准备目录> --collection-output-root <新续采目录> --reason "连接中断，保留原件并只续采失败和未开始请求"

# 使用新队列和新目录续采；原失败记录、成功响应及累计请求数保留。
python scripts/collect_universe_gaps_v1.py --batches <新续采准备目录>/ACQUISITION_BATCHES.json --output-root <新续采目录>

# 校验已完成的公司行动资料，生成新的正式数据清单及剩余缺口。
python scripts/prepare_universe_actions_v1.py --manifest <补充资料清单> --acquisition-root <原主采集目录> --additional-acquisition-root <追加采集目录> --additional-acquisition-root <续采目录> --legacy-catalog <旧资料登记目录JSON> --output-dir <新目录>
```

采集中可以用 `--manifest-name manifest_actions_partial_v1.json` 生成阶段检查清单。追加队列为 `ADDITIONAL_ACQUISITION_BATCHES.json`；采完追加资料后，再准备新产物并传 `--additional-acquisition-root <追加采集目录>`。阶段记录保留，不能被最终记录覆盖。

同一台机器上的 BaoStock 采集只保持一个登录会话，主队列、追加队列和续采队列顺序执行，避免另一采集进程退出登录时干扰当前连接。显式续采只申请失败及未开始的请求，排除已经逐项验证成功的请求；续采状态继承原实际请求次数，不能换目录后归零。它仍使用本次资料补齐授权，不等于账户运行、独立验证或策略资格授权。

一次显式续采在原数据目录之外登记唯一计划和采集目录。重复创建另一份计划或改用另一采集目录会在登录前拒绝，同一目录可以核验恢复。旧版已生成的合法续采可用 `--register-existing --batches <续采队列> --collection-output-root <原续采目录> --reason <登记原因>` 仅新增这份登记，不改原件或启动网络连接。

较长队列可用 `--max-batches 250` 分段，再用同一清单和目录继续；每段保存状态并核验原件。后续若另一请求失败，可对该阻塞目录显式准备下一份续采，重新核验全部父链并继承累计次数。每个具体请求最多三次显式重试（连同原始请求共四次）；超过上限保留阻塞。未开始的请求移到后续清单不算重试，工具不会自动无限循环。

正式策略请求继续使用 `FULL_UNIVERSE_SUBMISSION_V1`，引用新登记的 `dataset_id`、`universe_id`，通过 `capabilities → preview → diagnose/scan → freeze → approval → approve → start → status` 执行。不提交自行缩小的股票列表。详见[全范围使用说明](FULL_UNIVERSE_RESEARCH.md)。

工程对照通过证明接口和账本一致；全市场补齐证明资料覆盖有所完成。它们都不证明策略盈利或未来有效。研究历史、已尝试候选和独立数据使用记录继续保留。

## 2026-10-02 阶段结果

旧 BaoStock 正式桥接已完成一次真实验证：同一冻结规则、同一日期、五万元初始资金，在旧入口和新入口分别运行正常、压力成本，共四个公共账户作业。两组各核对122个账户交易日，买卖决定和账户经济结果没有差异。新版本新增的分红税审计说明另按冻结事件、实际到账审计、税款时间和原税则逐项核对；原严格比较的 `MISMATCH` 记录保留，没有删除字段来冒充相同。只读复核未新建账户或再次消费预算。

这证明旧资料能接入新入口，不能代替全市场账户验收。完整目标仍为4,607只；原144只缓存缺项都找到了可读取的本地通达信 `DAY` 原件，属于本地资料导入问题。全部4,607只也都有可复用的旧 BaoStock 未复权日线原件，已核对状态、前收盘价及与通达信同日价格的配对。原件物理范围为2022-07-22至2024-07-31，本轮补齐窗口为2022-08-01至2024-07-31；更早的状态不由这批原件补造。状态时间仍为 `MODELED`，没有升级为当年可见的 `VERIFIED`。

公司行动采集的阶段快照为：主队列已有3,361项逐项成功原件，其中4项来自原阻塞批次；另16项年度口径纠正请求已成功。剩余15,043项已生成显式续采队列，需要顺序继续采集和核验。这些数值是请求资料数量，不是已有完整资格的股票数量。阶段公司行动清单、原失败及部分成功原件继续保留；当前进度以本机采集状态和续采回执为准，不能把未完队列写成全部完成。

本机证据保存在 `reports/baostock_universe_bridge_v1/`；公开仓库只保存源码和使用说明。原全范围计划的 U8（真实全范围账户、三板块交易与独立核账）仍未验收，不能因桥接对照通过就关闭该项。
