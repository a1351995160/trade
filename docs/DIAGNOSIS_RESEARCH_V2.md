# 有状态规则：诊断后生成，再做固定初筛

`DiagnosisResearchV2` 把新的买卖条件、持有期、冷却期候选接到原研究预算、公共账户和完整家族档案。统一生命周期的实现类型为 `DIAGNOSIS_V2`。

第一版范围固定为两只股票、100 万初始资金、最多两只持仓、单股最多 50% 暴露、504 个账户日。先验证旧完整家族的结算结果，只把成本和分段失败的定性原因交给模型。在第一次模型调用前，同时冻结数据窗口、规则账户输入身份、真正买入持有账户输入身份、初筛标准及预算。两种后端的身份算法不同，必须分别保留，不能通过改写身份假装相同。

每个合法候选先归档，再运行普通成本与压力成本账户；使用同日真正买持账户，按原冻结标准检查正净收益、最大回撤不超过 25%、两个 252 日段均有正的日净超额收益之和。状态规则在费用变化后可能有不同交易过程，因此核验相同规则、风险设置和执行费用，不强迫两个费用情景的决策逐条相同。完成本候选初筛后，下一次模型才获得其定性反馈。非法或重复候选仍占尝试额度；失败家族成员不会被删除。

正式登记从结算凭证、账户结果和初筛配置重新计算通过名单。所有 V2 正式登记必须提供有效初筛根目录；失败者仍保留在冻结家族及多重检验分母，只为通过初筛者开独立数据账户。历史初筛不是统计有效性证据，现有真实收益方法适用性及 V2 方法范围阻断继续有效。

## 实际运行

在源码稳定后执行，两个命令之间不能更改源码：

```powershell
$env:PYTHONPATH='src;.'
python scripts/run_diagnosis_research_v2.py create --root <新的研究目录> --seed-root <旧11账户目录> --data-root <历史data目录> --approval-statement '按完整计划执行两次有预算规则研究' --attempts 2 --json
python scripts/run_diagnosis_research_v2.py run --root <同一研究目录> --json
```

`status` 只读；`revoke` 撤销未完成工作；`handoff --calibration-path ... --not-before YYYYMMDD` 仅在有候选通过初筛时登记未来窗口。无候选通过不会消耗正式确认机会。模型中断无可验证回执、账户未结算等情形拒绝自动重试，不退还尝试额度。

合成 504 日测试证明编排、完整家族、成本初筛、定性反馈、正式交接及拒绝结论能贯通；真实数据和真实模型运行需另看运行目录的原始凭证，不能用测试结果替代。
