# 全范围策略研究：先扫描全部股票，再按信号买卖

你只需提交一份明确的策略规则。选择已登记的全范围数据后，系统遍历登记清单中的深圳主板、上海主板和创业板股票，计算信号，并在同一个账户里决定买哪些、卖哪些。五万元是一份共同资金，不会为每个股票或每个分批各复制五万元。

## 范围与数据准备

| 板块 | 本次支持代码 | 指标和买卖规则 | 交易制度 |
|---|---|---|---|
| 深圳主板 | `00xxxx.SZ` | 同一公共 V3 目录 | 按当日适用制度处理 |
| 上海主板 | `60xxxx.SH` | 同一公共 V3 目录 | 按当日适用制度处理 |
| 创业板 | `30xxxx.SZ` | 同一公共 V3 目录 | 按创业板历史制度处理 |

现有缓存盘点为 4,536 只证券，其中深圳主板 1,478、上海主板 1,681、创业板 1,377。这个数字只是已找到文件的库存，不是写死的范围上限，也不能证明历史上所有上市、退市股票都已包括。实际目标来自有身份的历史清单；缺行情或缺资格的股票继续留在覆盖分母，不能悄悄删掉后说“全市场完成”。科创板、北交所及券商实盘下单不在本版本范围。

“股票范围”和“同时持仓数”不同。范围可以有几千只，五万元账户仍只持有规则和风控允许的少数股票。价格太高而买不起一手时，系统保留现金及拒单原因，不虚构碎股成交。

## 怎样提交

先用公共 `capabilities` 查询登记数据及指标目录。部署配置采用 `FULL_UNIVERSE_DEPLOYMENT_V1`，请求采用 `FULL_UNIVERSE_SUBMISSION_V1`。请求引用登记的 `dataset_id` 和 `universe_id`，**不提交自行缩小的 `symbols` 列表**。策略规则仍为公共 V3 JSON，正常成本和压力成本分别运行。

下面展示请求外层。`rule` 必须换成能力目录生成的完整示例或合法的 V3 规则，其他占位值换成维护者登记的实际引用；示例不授予数据或账户权限。

```json
{
  "version": "FULL_UNIVERSE_SUBMISSION_V1",
  "strategy_id": "my_frozen_strategy",
  "dataset_id": "registered_full_universe",
  "universe_id": "registered_history_main_and_chinext",
  "rule": "此处替换为完整V3规则对象",
  "feature_start": 20220407,
  "account_start": 20220706,
  "account_end": 20240731,
  "initial_cash": 50000,
  "max_positions": 2,
  "max_symbol_exposure_bps": 5000,
  "costs": ["BASE", "STRESS"],
  "benchmark": "CASH_AND_PRICE_REFERENCE",
  "purpose": "EXPLORATORY",
  "authorization_ref": "registered_existing_authority"
}
```

全范围 CLI 使用同一组公共命令：`capabilities → preview → diagnose/scan → freeze → approval → approve → start → status`，完整命令见[日常使用说明](AUTONOMOUS_RESEARCH_USER_GUIDE.md)。页面选择全范围数据目录后会自动引用全部登记目标；股票代码输入框隐藏。旧数据目录的指定股票请求继续走旧版本，不能用旧请求偷偷升级市场范围。

预览只读取登记元信息，不读取行情或授权交易。全范围诊断 `diagnose` 在已有数据授权内检查全部目标的字段、状态与事件覆盖，返回具体缺口；它不计算策略信号、不创建账户预算，也不授予账户权限。同一身份的诊断再次查询只复用原记录，不谎称重新读取了原件。全范围冻结复用公共信号检查已在受限工作进程内保存的输入，在主进程只核对回执和输入元信息，不重新加载全市场行情；资料齐全才可能形成可批准的账户计划。账户工作进程仍核对原件、规则、板块政策和资金条件。改变数据、来源、规则或制度后，需要重新预览，不能沿用旧身份。

### 只检查信号，也有统一入口

`scan` 在同一份已登记数据权限内，先保存规则、全部目标名单和授权引用，然后才读取行情。数据准备、输入冻结、资格检查及必要指标计算全部在同一个受限工作进程内：最多900秒、2048MiB内存、一个数值线程。超出限制就保留未完成原因，不声称已经完整计算，也不会自动改成几只股票。

报告分开记录三件事：登记目标几只、完成资格检查几只、真正计算条件几只。缺来源证据、当时不可见的证券状态、分红资料不完整或指标必需字段缺失时，这只股票的条件保持“未知”。例如检查了4607只、没有任何股票具备条件计算资格时，应显示“4607只已检查、0只实际计算、条件未知”，不能写“没有买入信号”。

有资格的股票继续使用同一个 V3 指标目录和组合表达式。原始买入、卖出及同股过滤条件的命中次数，不等于真实买入、卖出或止损成交次数；账户是否有现金、是否持仓、能否成交，还需要账户链路判断。因此信号检查没有账户收益，没有策略资格，也没有创建或消费账户研究预算。

相同研究目标、规则与日期沿用同一扫描意图。重复提交只读已有结果，不能重新获取免费扫描；原件登记信息、文件状态或源码改变会拒绝复用。查询旧记录会明确标记“已有记录”，不会冒充重新核验。意外中断保留原意图并要求核对，不能另换目录绕过记录。登记元数据的副本和原文件分别记录哈希，副本不冒充原始字节来源。工作进程使用已核验的原登记文件，原文件的编码、字段排列或BOM不会被重写成新的来源身份；诊断和冻结继续比较同一输入身份。

## 技术指标和止盈止损

三个板块使用[同一能力目录](RESEARCH_CAPABILITIES.md)中的指标版本、参数与输出。可以买卖条件组合使用 MA、MACD、KDJ、RSI、波动率等；不是只支持单指标，也不要求每个策略堆满全部指标。真正所需的字段和预热长度由规则决定。

“预热”指计算指标所需的过去数据。例如刚上市的股票暂时不够长，显示预热不足，不填补虚构历史。需要换手率的规则缺真实换手率时明确拒绝；不需要它的规则不会强制采集。缺失指标不等于“条件为假”，不能算作正常扫描无信号。

`market_filter` 名字容易误解：当前只允许同一股票的价格、成交量等字段，不能拿它声称已经使用大盘指数或行业排名。按波动率跨股票排序和 ATR 止损仍未接通；计算波动率或 ATR 指标不等于支持这两项执行功能。

成本止损、固定止盈、移动止损位于 `rule.exits`。它们在收盘确认，随后合法交易日的开盘尝试执行。停牌、跌停、流动性不足或跳空都可能影响成交；不会保证按止损线价格卖出。三个板块按各自适用制度执行，不把创业板标成主板。

## 公司行动和交易中断

日历独立于行情。未上市、已证实停牌、真实零成交量、正常交易却缺记录、状态未知分别处理。停牌不补一根假的 OHLC，不更新虚假的持仓价格峰值；持有天数仍按冻结交易日历计算。已持有股票退出选股范围后也继续管理和核账。

现金分红保存登记日、除息日和原支付日。延迟发放时，除息后先记“应收红利”，到账前不能当现金买入。全范围退出价格在除息后计入已确认归属的含税应收红利，避免把正常除息误当成亏损；这是新版本独立绑定的价格政策，旧路径的同日支付、已付红利比较政策不被改写。卖出获息股份按持有期计算补税，成交时扣款明确标为模型时间，没有冒充已核对券商实际扣款时刻。

送转、配股或退市结算资料不足会阻断完整账户结论。不会删除这些事件、把未知持仓清零或只保留没有麻烦的股票。

中断后沿用同一冻结输入、来源和预算记录。已经保存的交易和已消费研究额度不能再次记账或回退；恢复必须提供与连续运行一致的证据。页面刷新和状态查询不启动采集、模型调用或恢复。

账户工作进程中断后，可以先查询原任务，再手动选择“核对并恢复原全范围账户任务”，或调用公共 `resume` 命令。按钮只针对新版本未结算账户任务；后端仍要核对原进程已经退出、逐日保存记录有效、原授权未过期和剩余时间。它不创造新的预算、不改原规则，也不自动恢复。信号检查中断与账户恢复是不同状态，不能用账户 `resume` 偷偷重扫信号。

## 怎样理解结果

| 看到的结果 | 能说明什么 |
|---|---|
| 找到全部缓存 | 文件在机器上；字段与来源还需核对 |
| 完成全范围扫描 | 登记目标逐只得到信号或具体缺口说明 |
| 账户核对通过 | 现金、持仓、费用、分红和权益能独立重建 |
| 历史收益为正 | 这个冻结条件在已研究历史中盈利 |
| 独立验证通过 | 冻结规则后，在未用于设计的数据上取得相应证据 |
| 获得正式资格 | 原资格服务依据适用方法允许进入后续阶段 |

没有账户结果时，不展示“策略盈利”；零成交或少数交易的超额收益也不自动证明有效。分阶段表现、尝试过的所有候选、收益集中度和数据使用历史必须保留。

五万元通常不能整手等权买下几千只。全范围报告因此分开显示现金基准和“非可投资的期初等权价格对照”：后者允许理论碎股、没有交易费、固定期初名单且不再平衡，不是可以照着买的账户，不能据此授予资格。分红、停牌、后续 IPO 和未知退市处理有明确口径；缺资料时显示不可计算，不能重新加权剩余赢家。

新全范围路径的工程验收、真实全范围验收及三个板块分项证据单独记录。旧 V3 发布包只覆盖原声明范围，不能覆盖新增来源、全范围股票或创业板。当前能力查询仍显示 `ENGINEERING_NOT_ACCEPTED` / `REAL_NOT_ACCEPTED`，直到有本版本可核对的交付证据；工程通过也不代表已找到合格盈利策略或积累了真实 Paper 观察。

更多操作与接手说明见[任务运行与恢复](RESEARCH_LIFECYCLE_OPERATIONS.md)。回滚时停用新部署版本并保留新输入、失败、交易和预算记录，不修改旧合同、不退款已消费额度。

## 固定规则验收入口

维护者可用 `scripts/run_full_universe_acceptance_v1.py` 一次编排两套固定规则：单类均线规则，以及均线、RSI、波动率与同股量能组合。每套规则分别跑正常和压力成本，均引用全部登记目标、同一套指标目录及一份五万元账户，并输出现金对照和不可投资的价格对照。规则和检查标准在读取行情前保存；这里检验链路，不要求策略盈利。

验收配置使用 `FULL_UNIVERSE_ACCEPTANCE_CONFIG_V1`，只包含 `version`、`dataset_id`、`universe_id`、`feature_start`、`account_start`、`account_end` 和 `authorization_refs`。最后一项分别引用 `single_indicator` / `multi_indicator` 两个已有授权编号。脚本不能签发授权、创建研究目标、扩充预算或调用自写撮合器。

```powershell
python scripts/run_full_universe_acceptance_v1.py --workspace <工作区> --deployment-config <部署配置.json> --acceptance-config <验收配置.json> --output-root <验收报告目录>
```

默认只固定规则并完成数据诊断。已有账户许可明确覆盖两套规则、正常/压力成本、全目标、日期与五万元条件后，同一命令加 `--execute` 才会经过公共冻结、批准和受限 worker 执行。缺数据时保持完整目标分母，并输出具体等待原因。未完成冻结保留原任务供恢复，不换目录重开免费试验。工程夹具的账户通过仍不能称为真实全范围验收或策略合格。
