# 研究策略 V2：让 AI 改变交易行为

V2 允许 AI 分别说明什么时候买、什么时候卖、至少持有多久、最晚何时退出、卖完后等待多久，以及单证券的目标仓位。它仍然提交可审核的规则，不运行 AI 生成的 Python。

原 51 指标投票规则保留原版解释。新规则不必同时使用 51 个指标；例如 MACD 的两个不同输出可以比较，也可以与价格、成交量条件组合。目录中的指标版本、公式和参数固定；此版本不开放任意参数搜索。

## 能力与边界

| 业务能力 | 固定语义 |
|---|---|
| 比较和阈值 | 大于、小于、等于、区间，输入为已注册指标输出或合格行情字段 |
| 交叉 | 必须有相邻两次合格观察；缺口不产生交叉信号 |
| 条件组合 | 与、或、非，复用现有 `conditions_v2` 三值逻辑 |
| 买卖条件 | 分开冻结；同时成立时退出优先 |
| 持有期 | 按真实成交的交易日序号计算；不是按下单日期或自然日计算 |
| 冷却期 | 全部卖出后经过规定数量的完整交易日；卖出当天不重新买入 |
| 仓位 | 单证券目标权重 1%—100%；已有持仓不因每日信号反复加仓；共同账户还须限制总资金 |
| 市场过滤 | 首版只允许当前证券的合格价格和成交字段，不能引用未知外部市场状态 |
| 缺数 | 不把未知条件当作看空，也不新增买入；已到期或已经发出的退出继续保留 |
| 恢复 | 持久化规则身份、上一决策交易日及待退出状态；未全部成交的退出继续有效 |

表达式最多 6 层、每个条件 64 个节点，与/或最多 4 个分支。历史引用最多 60 个交易日，禁止负数引用、居中窗口和任意代码。持有期上限 252 个交易日，冷却期上限 60 个交易日。最短持有期不能超过最长持有期。

持有期规则只决定收盘时是否发出退出意图；下一交易日开盘、T+1、停牌、涨跌停、部分成交、整手和现金限制仍由原交易引擎处理。退出意图不表示已经卖出，冷却只能从真实账户全部退出的交易日开始。最短持有期限制常规卖出条件；最长持有期和已在途退出不因缺指标而失效。

## 入口和冻结格式

`research_rule_strategy_v2.py` 提供：

- `rule_capabilities()`：向 AI 提供白名单、所有注册输出及边界。
- `validate_rule_payload(payload)`：拒绝未知字段、输出、版本、参数和未来引用，返回规范化规则。
- `ResearchRuleStrategyV2(payload, strategy_id=...)`：公共 `CloseStrategy` 适配器，输出原 `Decision/TargetWeight`。
- `build_feature_matrix(bars, vendor_turn)`：按已有注册表计算被引用的全部输出；调用方先按已知公司行动构造因果指标价格，成交行情仍用原始价格。

payload 必须恰好包含 `version`、`hypothesis`、`change_reason`、`buy`、`sell`、`market_filter`、`min_hold_sessions`、`max_hold_sessions`、`cooldown_sessions`、`target_weight`。`version` 为 `RESEARCH_RULE_STRATEGY_V2`，`market_filter` 可以为 `null`。表达式沿用原条件层的 `{op, args, params}`；指标引用必须显式指定目录中的 `version` 和 `output`。

规则身份绑定指标目录与实际执行语义，不因修改假设说明而变为新策略；完整公共计划仍包含说明和源码身份。调用方使用同一规则身份进行家族判重、账户运行与归档，不能靠改文字获得新预算。

## 接入共同账户与 Paper

旧 S1 后端和旧 Paper 的空账户预生成方式不足以运行 V2；新的调用方必须每个实际收盘调用一次公共策略，并提供真实账户投影。不得把空字典补默认值后声称已经接通。

`Context.history` 必须严格等于冻结交易日日历截至当前日的前缀；缺交易日保留缺值，不跨缺口压缩。指标列名为 `<indicator_id>.<output>`，就绪列名为 `<indicator_id>.<output>__ready`。没有输出或就绪证明视为未知。

`Context.account` 恰好包含以下四项，由同一证券在真实账本中的仓位和成交记录生成：

| 字段 | 来源 |
|---|---|
| `quantity` | 当前剩余持仓数量 |
| `sellable_quantity` | 当前可卖数量；不得大于持仓 |
| `entry_session_index` | 当前持仓首次真实入场序号；空仓为 `null` |
| `last_exit_session_index` | 最近一次全部卖出的真实成交序号；从未退出为 `null` |

调用方保存 `Decision.state`，下一交易日原样放入 `Context.state`。首次调用允许空状态，以后必须严格连续。中断恢复从已提交检查点恢复账本和状态；不将本日输出状态重新用于本日调用。公司行动不能重置入场时间或伪造退出。

`TargetWeight(0)` 是退出请求，`TargetWeight(w, increase_existing=False)` 是空仓入场请求。多证券调用方先收齐退出意图，再依据共同账户资金分配买入；本模块不创建子账户、不自行撮合和记账、不授予正式策略资格。

## 验证范围

`test_research_rule_strategy_v2.py` 覆盖规则边界、注册多输出、缺值、交叉、买卖冲突、实际成交日持有、冷却、部分退出和状态恢复、篡改及非法表达式。实际测试结果由整计划的统一运行报告记录。

这些测试只验证规则语义。公共回测、Paper 和 AI 入口必须另外用同一规则完成逐日决策与账户核对，才能声明 U5 已贯通；合成测试通过不代表策略有效。统计适用范围也不能自动继承旧投票规则的结论。
