# 分红、送转和日期冲突处理

本说明解释全范围研究入口的公司行动处理。公司行动是分红、送股、转增等会改变现金、股数或价格的事项。旧现金账户保持原行为；账户窗口内有送转事件时使用 `UniverseCorporateAccountingV2`。

## 用户能得到什么

同一股票的行情、股份和现金会一起计算。例如持有1,000股，公告每10股转增3股并派8元，股份权益增加300股，含税分红为800元。总持仓成本保全，单股成本随股数变化；到账前的红利是应收款，不能用来买股票。新股份按明确的到账日和可交易日处理。

送转后的原股、新股使用相同的止损比较口径，继承转增前已形成的移动保护峰值。收盘确认出场、下一合法交易日开盘撮合；实际成交仍使用未复权价格。同一股票当天所有订单共同使用前日成交量限额，同日恢复不能重新获得额度。

独立核账另行计算股数、成本、分红、税、到账、可卖数量、成交容量和逐日资产。核账通过不证明策略有效。测试通过也不替代真实公告和真实账户验证。

## 资料完整度分成两层

| 层次 | 要证明什么 | 缺资料时的结果 |
|---|---|---|
| 价格与指标 | 日期、分红金额、总送转比例和原始除权参考价格一致 | 对应股票保持价格未知，保留在扫描名单中 |
| 账户 | 另有税务来源、股份到账及可交易日期，且持仓能精确分配 | `account_complete=false`，不能宣称整池账户已跑通 |

`CORPORATE_ACTION_COVERAGE.json` 的 `complete` 表示价格覆盖；`account_complete` 表示账户条款覆盖。`coverage_version=CASH_AND_SHARES_V2` 明确区分二者。全股票池分母不因缺资料变化。

指标使用因果后复权：公司行动只改变生效日及以后的指标输入，过去的决策不被后来发生的分红改写。送转后成交量换算到原股单位，成交额与指标价格口径配套。来源中的原始价格和成交数据保留。

## 同一天多笔分红

两个不同金额不能直接证明有两个方案。准备器要求有来源绑定的公告审核声明，说明独立项目、登记日、支付日及每股金额，原始响应身份也必须一致。真正的修订冲突仍保留未知。

实际派息与除息价格参考可能不同，例如回购股份不参加分红时。账户使用实际每股现金，指标价格校验使用公告中的除息现金参考项 `price_terms`。两者分别保存，不能相互替代。

## 送转税务和到账证明

资本公积转增不能一律按免税处理。只有公告明确证明来源为股本溢价，并有适用税务依据时，才使用 `CAPITALIZATION_SHARE_PREMIUM_EXEMPT`。未知资本公积来源继续拒绝账户执行。

有明确送股计税条款的工程模型支持 `BONUS_DEFERRED_INDIVIDUAL_2015_101`，但税权在新股lot上的分配明确为 `CHILD_LOTS_MODELED`，`tax_allocation_verified=false`。这不是中国结算或券商实际扣收认证。

正式补证声明绑定公告原件哈希、派生文本哈希、来源URL、发布日期和引文。引文须存在于绑定文本中；声明标为 `SOURCE_BOUND_REVIEWED_DECLARATION`、`automatic_document_semantics_verified=false`。这些是审核后的条款输入，系统不声称自动理解PDF或完成法律认定。

## 日期差异的复验

`resolve_universe_action_dates_v1.py` 将每个疑似差异分类，绑定原始复权响应、交易日历、原价及输入来源。`verify_action_date_resolution_receipt_v1` 只读重算条件；哈希一致本身不够。源码、输入、来源或比较条件变化均拒绝旧收据。

本次已证明的解释包括累计因子未变化的单位锚点、上市首个报价的单位因子行，以及原价连续的单位初始锚点。这些解释只说明该因子行不能证明新增除权，不证明完整历史上市清单，也不升级历史信息可见时间。

真正累计因子变化、无法解释的字段变化、或分红日缺复权行，继续出现在按证券和日期生成的补证队列中。

## 准备方式

维护者先复用原件，再生成新的版本化数据。旧目录、旧清单和旧回执不得原地改写。

```powershell
python scripts/resolve_universe_action_dates_v1.py --source-catalog <原件目录清单> --gaps <原缺口> --manifest <原登记清单> --market-catalog <原价来源清单> --output-dir <新日期证据目录>
python scripts/prepare_universe_actions_v2.py --manifest <原登记清单> --source-catalog <原件目录清单> --action-gaps <原缺口> --action-resolutions <新日期收据> --share-terms <股份补证声明> --cash-components <独立分红项目补证声明> --output-dir <数据根中的新目录> --manifest-name <新清单名.json>
```

股份声明版本为 `UNIVERSE_SHARE_TERMS_RESOLUTIONS_V1`，现金项目声明版本为 `UNIVERSE_CASH_COMPONENT_RESOLUTIONS_V1`。准备结果分别输出 `PRICE_GAPS.json`、`ACCOUNT_TERMS_GAPS.json` 和来源清单。旧原件未必带有完整接收时钟；沿用其原登记协议，保持 `legacy_receipt_clock_verified=false`，不补造采集回执。

策略继续提交原有公共 `run_trusted_research_v1.py` 入口。新数据清单由维护者登记，策略不能自行替换来源、缩小目标名单或把未知条款改成零。封存数据限制仍在读取和哈希前检查；股份到账与上市日期也检查封存范围。

## 当前边界

以下情况仍需明确证据或额外实现：非整数赠股的账户级分配、登记后到除权前持仓权益变化、同日多个未合并股份比例、配股及未知退市清算。系统会给出具体原因，不以近似整数、默认免税或删除股票取得账户通过。

回滚代码可以回退本次功能提交；数据登记切回旧版本清单。保留新旧冻结任务和来源目录，新功能回滚不改写既有研究次数或已消费预算。
