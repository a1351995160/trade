# 全范围策略研究交付与真实数据边界

本次将深圳主板、上海主板和创业板接到同一公共策略入口。提交规则后，扫描登记的全部目标，按信号产生候选，由一份资金统一决定成交；分批计算不会复制账户资金。技术指标、指标组合、成本止损、止盈、移动止损、核账和手动恢复使用同一业务流程。

**软件验证与真实全范围账户验收分开。** 本机有大量真实价格记录，但历史可见时间、公司行动与交易参考价仍有缺口；不能因合成测试通过就称真实全范围回测完成，更不能称找到了有效盈利策略。实施计划因此保持 `active`。

## 怎样使用

流程为：查询能力 → 提交V3规则并预览全范围 → 查看数据缺口或检查信号 → 冻结 → 使用已有授权批准 → 运行账户 → 独立核账 → 查看报告。

全范围请求引用维护者登记的 `dataset_id` / `universe_id`，不手填几只股票。公共 `scan` 把数据准备、冻结、资格检查和原始条件计算放在同一受限工作进程，最多900秒、2048MiB、一个数值线程。`freeze`复用这次检查的固定输入，宿主不再次加载全市场表。原始条件命中不是买入成交，不提供账户收益。

`diagnose`只检查数据，历史记录查询不重新读行情；它不运行策略或创建账户预算。工作台可以查看完整分母、三板块缺口及信号检查计数。没有算过的条件显示未知，不能用零信号代替。未结算账户可手动 `resume`；运行中的进程、过期授权、已结算失败或耗尽时间不能通过换目录免费重跑。

维护者准备的实际配置保存在本机 `reports/full_universe_runtime/`，数据在 `data/full_universe/`，均不进入公开Git仓库。原始路径和授权仍由可信部署登记，策略请求不能任意读磁盘。公共命令和配置格式见[使用说明](FULL_UNIVERSE_RESEARCH.md)。

## 为什么真实账户仍不能验收

1. **144只目标缺少可确认的行情来源。** 它们保留在全部目标分母中，没有为了回测成功被删除。
2. **证券状态在决定时不可确认。** 本次整理了486个交易日、2,239,002条状态记录，保留原件声明的“次日开盘可见”与模型性质；不能提前到当天收盘或开盘使用。
3. **公司行动覆盖不足。** 没有完整资料证明每只股票的分红、送转、配股和退市处理；缺文件不能改成“没有事件”。本计划也不新增非现金事件或退市清算算法。
4. **单位和交易参考价仍有证据边界。** 4,463只授权窗口的缓存与TDX原编码逐行一致，但这不能单独证明单位、官方除权参考价或历史可见性。缓存的前一有效收盘价不能冒充交易所的除权参考价。
5. **历史证券清单完整性尚未独立证明。** 当前登记范围可复算，完整历史市场的身份仍为未知，不能称没有遗漏退市证券。

上述缺口不是用新参数、额外候选或“扫描完成”标签能解决的。来源准备生成独立版本；`manifest_v4.json`补齐的是制度代码版本绑定，不提高原始数据的事实资格。原v1至v3、状态时间及公司行动缺口保持不变。
