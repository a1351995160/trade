## 为什么找到公告后还有缺口

公告有时明确写股份到账日期，却只说“资本公积转增”，没有说明这笔资本公积是否来自股本溢价。因此可以补齐到账证据，但不能默认免税。看到“转增金额未超过股本溢价余额”，也不能自动证明所有转增均来自该余额。

301019.SZ/20240711的公告明确不派现金，且股东每10股实际获得4.015392股；计算除权价却按全公司总股本折算。回购账户不参与分派，两种比例不同。原来源还有小数精度差异，现有价格路径需要分别表达这两种比例；本轮没有修改账户协议或放宽容差，这项继续阻断。

000796.SZ/20231220的重整专项意见明确新股不分给原股东，并采用特殊除权参考价。不能把总股本增加理解为原账户股数增加。日期资料、价格事件映射和真实股份分配安排需要分别处理。

其余未审核公告继续保留待审核；尚未在限定窗口取得公告、图片PDF没有可提取文字、取得公告但缺条款，分别列出，不能统一叫“没有数据”。

## 维护者如何复现

1. 冻结通达信清单、物理限窗导出及读取审计的路径与SHA，使用 `resolve_universe_numeric_terms_v1.py` 生成新回执。
2. 准备器以 `--numeric-terms` 消费回执，重新读取原件并重算零现金条件。原始空值保留，账户资料缺口继续输出。
3. `classify_universe_action_evidence_v1.py` 接受六个明确绑定的输入，输出分类和日期公告队列，保持原始未知状态。
4. 公告目标版本为 `UNIVERSE_ACTION_ANNOUNCEMENT_TARGETS_V1`；每项提供 `symbol`、`effective_date`、`kind`、`source_response_sha256`、`cninfo_org_id`、`publication_window`。可显式冻结包含主窗口且不超过14天的备用窗口。当前证券映射只用于定位历史发行人公告，不证明当年的可交易状态。
5. 运行 `fetch_universe_action_announcements_v1.py --targets <目标.json> --source-catalog <原目录.json> --output-dir <目标包下的新目录>`。PDF文字提取使用运行环境提供的 `pypdf`；缺少依赖时仍留存PDF并明确记录提取失败。原件保存不需要把来源包装成BaoStock。
6. 逐份读公告，审核后才生成 `UNIVERSE_SHARE_TERMS_RESOLUTIONS_V1`。准备器检查原件、文本和引文，再独立检查到账、可交易、税务及份额条件。

产物保存在本地 `reports/targeted_action_evidence_v2/`；当前派生清单为 `data/full_universe/manifest_actions_targeted_v3.json`。旧失败、旧算法精确快照、原件与旧冻结作业全部保留，真实研究资料不上传仓库。冻结回执绑定生成工作区的绝对路径和算法版本，主目录同步不改写这些身份；原工作区保留用于重放。换路径或算法时重新生成新版本。

回滚源码使用本次发布提交的 `git revert`；数据登记切回原 `manifest_actions_complete_v1.json` 或旧公司行动版本。回滚不删除原件，不重置研究次数、已经消费的预算或历史结论。

本轮未运行策略账户、创建研究预算、授予有效性或Paper资格。完整研究链路仍需公司行动缺口及其他证券状态、退市结算等条件通过后另行验收。
